# Literature review: benign tool-injection failures

Working synthesis; detailed chunk notes below will be condensed after resource validation.

## Sequential reading notes
- AgentDojo chunk 1 (pp. 1–3): dynamic mutable environment, separate user utility and attacker success checks; 97 tasks and 629 security cases. Clean tool capability is a confound, directly motivating the specified eligible-task denominator. Formal state checks avoid compromising an LLM-based environment simulator.
- AgentDojo chunk 2 (pp. 4–6): Python utility/security predicates inspect state and output; manual tasks and inspected fictional fixtures; attack placements follow ground-truth tool traces. Reports benign utility, utility under attack, and targeted ASR separately. Reuse these distinctions; do not equate failed utility with attacker success.
- AgentDojo chunk 3 (pp. 7–9): more capable models can also be more attackable; attacks degrade utility by 10–25 percentage points. Tested ignore-previous, InjecAgent, TODO, and important-message payloads, plus delimiters, detection, repeated user prompt, and tool filtering. Tool filtering reaches 7.5% ASR but can restrict needed dynamic tools. Position and task type strongly affect results; fixed payload families and balanced positions are necessary.
- AgentDojo chunk 4 (pp. 10–12): limitations include task/environment extensions and constrained attacker settings. References identify foundational indirect injection, spotlighting, structured queries, and ToolEmu; these are context rather than evidence for the proposed 0.10 threshold.
- AgentDojo chunk 5 (pp. 13–15): references and reproducibility checklist. Dummy data rather than real users; reported confidence intervals use proportion estimates. Our paired contrast requires paired uncertainty instead of subtracting independent binomial intervals.
- AgentDojo chunk 6 (pp. 16–18): appendix provides modular attack/pipeline interfaces and different model-specific function-calling prompts. Record the exact chat template/parser and reasoning setting for each checkpoint; interface differences confound checkpoint comparisons.
- AgentDojo chunk 7 (pp. 19–21): exact baseline payload and appendix result tables. Version inconsistency: abstract/main text's older <66% utility contrasts with Table 3 Claude 3.5 Sonnet 78.22% and GPT-4o 69.00%; use table-specific values and do not mix versions. Table 4 important-message targeted ASR 57.57%, versus 5.72% InjecAgent in that setup. End placement is stronger; this is not the matched benign-control effect under study.
- AgentDojo chunk 8 (pp. 22–24): MIT code/data with inherited exceptions, synthetic fixtures, versioned tasks, reproducibility materials. Data-card total 124 includes user plus injection tasks, not 124 independent clean user tasks. Pin code revision and suite version.
- AgentDojo chunk 9 (pp. 25–26): data generation and validation inspect consistency and verify ground-truth traces. Fixed attacks cannot establish general robustness; our study estimates a prespecified causal contrast, not resistance to all adaptive attacks. Full 26-page review completed.
- InjecAgent chunk 1 (pp. 1–3): 1,054 cases = 17 user cases crossed with 62 attacker instructions; generated with GPT-4 and manually refined. Tool response templates contain a controlled attack placeholder. This structure is useful, but 1,054 cases are not 1,054 independent task templates. ReAct GPT-4 summary ASR is 24%, enhanced 47%; these are not clean-eligible paired estimates.
- InjecAgent chunk 2 (pp. 4–6): assumes the initial tool call already succeeded and evaluates continuation, rather than full clean tasks. ASR-valid excludes malformed outputs; ASR-all includes them. Parser failures and correct arguments matter. Table 3 gives prompted GPT-4 23.6% base and 47.0% enhanced ASR-valid, finetuned GPT-4 6.6%/7.1%. Use local state effects rather than this benchmark's tool-name-oriented outcome alone.
- InjecAgent chunk 3 (pp. 7–9): user-case variation associates more strongly with ASR than attacker-case variation; high-freedom content slots are more vulnerable. Enhanced prompts may also increase attack recognition. Balance task templates and keep the insertion field fixed; assess benign edits separately from harmful-intent refusal.
- InjecAgent chunk 4 (pp. 10–12): limitations explicitly include one fixed enhanced prompt, minimal mixing of benign and injected content, one interaction, and at most two attacker actions. These make it a template source rather than a ready-made test of the exact hypothesis; reference section checked.
- InjecAgent chunk 5 (pp. 13–15): complete model versions, temperature zero, only relevant user/attacker tools exposed, and a synthetic prior assistant Thought included. Valid rate is correlated with general capability; avoid importing the synthetic Thought into the main native-tool experiment.
- InjecAgent chunk 6 (pp. 16–18): Appendix C includes InjecAgent-clear with three benign tool responses per user case. This is an important prior clean control, but measures valid output rather than the exact paired length-matched quotation/record-edit contrast. Do not claim clean controls are absent from prior work.
- InjecAgent chunk 7 (pp. 19–21): ASR-all, attack-type, and unsuccessful-response-quality tables are distinct endpoints. Prompted GPT-4 ASR-all 23.3%/46.8%, slightly different from ASR-valid; record denominators explicitly. Quality ratings on failed attacks are not task completion.
- InjecAgent chunk 8 (pp. 22–24): short-ReAct-prompt tables and case heatmaps reinforce sensitivity to wrapper and template. Do not vary the wrapper between injection and quotation arms or count repeated attacker/user combinations as independent tasks.
- InjecAgent chunk 9 (pp. 25–27): content freedom examples, successful/failed traces, and full prompt start. A failed exfiltration can still involve an unauthorized first action; record attempts, intermediate writes, target achievement, and final state separately.
- InjecAgent chunk 10 (pp. 28–30): exact ReAct formatting, no invented tool arguments, helpfulness/autonomy and risk-confirmation instructions, and shorter prompt. Native tool calls should receive strict schema validation; a fictional harmless edit still tests authorization rather than harmfulness.
- InjecAgent chunk 11 (pp. 31–33): generation requires feasible tasks, realistic editable text fields, exactly one placeholder, and consistent tool schemas. Adapt these constraints to benign fictional records; keep ground-truth values outside the attacker-controlled slot.
- InjecAgent chunk 12 (pp. 34–36): remaining attacker-generation and simulated-response prompts; actual data-exfiltration execution is outside this study. Full 36-page review completed. The reusable contributions are schemas, controlled placement, and valid/all reporting, with fictional state execution substituted for simulated tool success.
