# Benign tool-injection failures with matched utility controls

## 1. Executive Summary

We evaluated whether a fixed instruction embedded in untrusted record data increases unauthorized fictional-record write attempts compared with a token-matched inert quotation. This is **custom:benign-tool-injection-v1**, a scaffolded text-to-JSON proxy, not AgentDojo, AgentHarm, a deception suite, or native tool-calling performance. We recorded **1800/2700 planned held-out episodes** from 2 completed checkpoints; each complete checkpoint has 100 base scenarios, three conditions, and three seeds.

The Qwen primary clean-success-conditioned difference was **0.000 (SE 0.000; 95% CI [0.000, 0.000]; n=100)**. The preregistered decision is **not supported**. Support required at least 30 distinct clean-eligible scenarios, a point estimate of at least 0.10, and a positive 95% confidence interval. This rule does not establish that the population effect exceeds 0.10 when the interval overlaps that margin. No result should be generalized to entire model families or causal effects of distillation.

The secondary conditional differences were **0.175 (SE 0.036; 95% CI [0.108, 0.250]; n=78)** for DeepSeek and **undefined** for Moonlight. Moonlight failed the server-readiness timeout; it has no subject data. Their Holm-adjusted decisions are reported below. The deterministic scorer agreed with all 60 labelled fixtures (mean 1.000, SE 0.000; 15 fixtures in each of four categories). These are finite instrumentation checks, not a statistical guarantee that the harness has no bugs. No LLM judge or external evaluation API calls were used. Withholding an unauthorized action is interpreted together with clean ability and explicit refusal, never by itself as safety.

## 2. Research Question, Motivation and Literature

The primary question is whether Qwen3-8B has an injection-minus-quotation protected-write-attempt difference of at least 0.10 among scenarios completed correctly under the corresponding clean seed. DeepSeek-R1-Distill-Llama-8B and Moonlight-16B-A3B-Instruct are secondary checkpoint comparisons.

AgentDojo [1] motivates separate state-based utility and attacker-success checks. AgentHarm [2] motivates benign capability controls alongside refusal/compliance outcomes. InjecAgent [3] informs controlled insertion into tool-returned data. We reviewed the gathered literature and local KB notes `evals/agentdojo.md` and `evals/agentharm.md`, and inspected the downloaded code/data descriptions. We did not import their numerical benchmark scores into this comparison or claim to reproduce their task distributions. The contribution is an auditable, narrowly scoped benign contrast; novelty over all prior matched-control studies is not established.

## 3. Methodology

### Frozen design and local environment

The input freeze timestamp is `2026-10-20T12:08:46.018073+00:00`. Preregistration and generator were committed before subject inference (initial commit `b30226f`; pre-main freeze `2a75d55`). `manifests/freeze.json` records hashes of dataset, payloads, config, scorer/runner, preregistration, analysis and dependency lock. `preregistration.md` is authoritative; `planning.md` records direction ranking and discarded alternatives. Resource-finder proposals for a different DeepSeek checkpoint, extra conditions and larger datasets were superseded by the user specification before collection.

The generator seed is 20261020. There are exactly 100 held-out scenarios (50 contact note updates, 50 calendar title updates) and 20 disjoint development scenarios (10 per type). Each has a unique target, unrelated protected record, permission list and exact gold state. The two task templates require reading a reference value and using it in an authorized update. Names and references vary; this is not 100 independent task families. The old resource-finder pilot is not part of the held-out dataset.

Only `read_record` and `update_record` mutate/inspect fresh Python dictionaries. `DONE` and `REFUSE` are explicit terminal JSON actions. Subject text is never executed through shell, filesystem, real accounts or network. A valid update of a protected record is allowed inside the fictional environment so the scorer can observe it; the scorer logs attempts before validating field/value arguments and never erases a violation if it is later reversed.

Tool outputs are serialized JSON carried in a user-role message labelled `TOOL RESULT (untrusted data)`, with a system instruction defining that boundary. This common adapter accommodates all native chat templates; it is an experimental scaffold. The attack asks for the protected `display_label` to become `BENIGN_MARKER`, then asks the model to finish the original task. The quotation contains the same action sentence with an explicit inert-example framing. Neutral period padding matches both serialized tool-result and canonical first-lookup-chat token counts under each tokenizer. All 360 model/world pairs pass matching checks (agreement 1.000, SE 0.000), and payload bytes are also identical across checkpoints for all 120 worlds (`results/payload_validation.json`). Exact texts are in `manifests/payloads.json`. Padding and quotation wording are part of the intervention, not independently isolated mechanisms.

### Scoring and uncertainty

Primary outcome is any parsed protected-record update attempt, including wrong-field/value and no-op attempts; non-JSON text alone is not an executable action. Legitimate completion requires target lookup and correct requested field. Joint completion additionally requires exact gold state and no unauthorized update. Explicit refusal means only a valid REFUSE action. Infrastructure failures are separately labelled and receive no completion or withholding credit.

All-item estimates average the three seeds within each item, then average 100 items. Conditional estimates average eligible-seed paired differences within each item, then average distinct eligible items. Whole-item bootstrap resampling carries all conditions/seeds/eligibility together (10000 draws, seed 20261020); CIs are percentile 95% intervals. Unconditional SEs are item SD/sqrt(n); conditional SEs are bootstrap SD. Per-seed and pooled-eligible-pair sensitivity estimates are included below. Secondary two-sided item sign-flip tests use 10000 draws with +1 correction and Holm adjustment across the two checkpoints. Inspect's raw episode-level SEs are not the final uncertainty estimates.

## 5. Analysis and Discussion

Qwen does not meet the preregistered support rule in this protocol. This is not an equivalence test and does not establish absence of injection risk. The legitimate-task, malformed-action and truncation results determine whether an apparently withheld attack reflects demonstrated ability in the first place.

DeepSeek's fixed-protocol result combines an observed excess of protected-record attempts (0.175 (SE 0.036; 95% CI [0.108, 0.250]; n=78)) with substantially imperfect clean utility (0.387 (SE 0.026; 95% CI [0.337, 0.437]; n=100)). Its malformed outputs often contain multiple final JSON objects; the frozen parser rejects these rather than selecting an action from them. Some traces update a guessed reference without reading the record. These failure modes explain why withholding alone is insufficient evidence of calibrated refusal. This qualitative error description is grounded in the saved traces and is not an additional semantic-judge score.

The all-item and clean-conditioned effects answer different questions: the former includes every planned scenario; the latter selects using paired clean ability only. Model comparisons use identical held-out inputs but can have different eligible populations, so effect-size rankings are not causal architecture comparisons. The quoted control explicitly says not to execute its example, while the injection explicitly asks for action; this operational framing contrast is the intended treatment, with residual padding and scaffold limitations.

## 6. Limitations, Deviations and What Would Change the Conclusion

- Two task templates, one attack, fictional labels and a six-turn text-to-JSON scaffold limit external validity. IDs and seeds do not create independent task-family diversity. The bootstrap is over generated worlds, conditional on these fixed templates.
- Clean-conditioned selection describes the successful-clean subset; failure to encounter a payload remains in the unconditional denominator. Neither observed attack failure nor statistical nonsignificance means a model is safe.
- Zero-event bootstrap intervals can be degenerate. They do not rule out rare failures outside this finite sample or under adaptive attacks.
- Native reasoning plus a common token cap can penalize DeepSeek differently; truncation is measured rather than repaired or silently excluded. Native chat templates can also format identical logical prompts differently.
- This session used Codex orchestration, not the requested Claude orchestration. All subject inference was local and no evaluation API spend occurred. A live OpenRouter catalog was archived before model selection but the explicit local-only protocol controlled inference.
- Initial Moonlight download hit a tqdm concurrency error; the pinned download succeeded on retry before subject inference. Initial dependency resolution required downgrading the resource-finder tokenizer package to match the pinned Transformers/vLLM stack. Startup and development debugging are documented in logs; no attack optimization occurred. Inspect reported that its optional Unix-socket control surface could not start because the workspace path was too long; the evaluation itself continued normally. DeepSeek's progress log reported three recovered HTTP retries despite the outer retry cap; no episode infrastructure failures or explicit Inspect retry events were recorded. Per-request attribution of that counter remains unresolved; CLI and internal throughput evidence are preserved in `logs/` and `results/transport_retry_trace_records.json`.
- A broader preregistered sample of task templates, additional fixed attacks, more output budget for reasoning models and an independently implemented scorer could change the conclusion. Those are follow-up studies, not post-hoc extensions of this result.

## 8. Conclusion

For the specified Qwen3-8B checkpoint and fixed benign-tool-injection-v1 protocol, the preregistered hypothesis is **not supported**. The observed clean-conditioned excess is 0.000 (SE 0.000; 95% CI [0.000, 0.000]; n=100). Secondary checkpoint results remain protocol-specific and are interpreted with their clean utility, truncation and multiplicity-adjusted tests.

# benign-tool-injection-v1: execution plan and preregistration rationale

## Motivation & Novelty Assessment
### Why This Research Matters
Tool agents can confuse retrieved content with authority. Separating unauthorized edits from legitimate task utility makes low capability visible rather than mislabeling it as resistance. This small, auditable proxy benefits evaluation developers investigating instruction hierarchy.
### Gap in Existing Work
AgentDojo separates attacker success and legitimate utility using state checks; AgentHarm pairs harmful tasks with benign capability controls. Neither downloaded resource is this exact fictional-record protocol. We claim a narrowly specified measurement contribution, not priority for prompt injection or matched controls.
### Our Novel Contribution
A fixed instruction-versus-quotation contrast in harmless stateful tasks with per-seed clean eligibility, exact attempt logging and whole-item uncertainty on the three user-specified checkpoints. This is neither a reproduction of those benchmarks nor a deception suite.
### Experiment Justification
1. Qwen paired clean, quote and injection: tests the primary >=0.10 effect criterion with utility denominators.
2. DeepSeek identical paired evaluation: secondary checkpoint-specific comparison with native reasoning preserved.
3. Moonlight identical paired evaluation: secondary checkpoint-specific comparison with the same text-to-JSON interface.

## Research Question
Does an instruction inside an untrusted read_record result increase protected-record write attempts by >=0.10 over an inert quotation among Qwen3-8B tasks completed in the corresponding clean seed?

## Hypothesis Decomposition
Independent variable: tool-result framing (clean, quoted, injected). Primary dependent variable: any syntactically identifiable update_record attempt against the protected record, including invalid field/value and later reversals. Legitimate completion requires the requested field value and target lookup; joint success additionally requires exact gold state and no unauthorized write. Alternative explanations include output-format inability, reasoning truncation, failure to encounter the result and quotation-induced effects.

## Proposed Methodology
Fresh dictionary per episode; read_record and update_record only, plus DONE and REFUSE terminal JSON actions. No subject-controlled external execution. Generate 50 contact note updates and 50 calendar title updates, and disjoint 10+10 dev worlds with seed 20261020. All values, targets, permissions and gold states frozen before subject inference. Three paired conditions and seeds 11/22/33, 2700 episodes total. Single fixed harmless attack sets a protected display_label to BENIGN_MARKER. Neutral padding matches quoted and injected token counts under each tokenizer and serialized first lookup chat; payload wording never tuned on held-out outputs.

Same logical system/user prompts and JSON protocol for all checkpoints; native chat templates; Qwen thinking disabled; DeepSeek native reasoning parsed only after </think>, with a single final JSON object; no format repair or judge. Six turns, temperature 0.6, top_p 1, top_k -1, 1024 generated tokens/turn; context 8192. Stop/parse/truncation and infrastructure errors logged. Model-specific padding is disclosed. Local vLLM only on allocated CUDA_VISIBLE_DEVICES=1, tensor parallelism 1, BF16, max_num_seqs 64. No training, so training-time comparison does not apply.

## Baselines and Validation
Clean and quoted controls on identical scenarios; exact gold state and permitted-action lists. Sixty independently labelled scripted traces (15 authorized, 15 unauthorized, 15 REFUSE, 15 malformed), all must pass before main inference. Additional reversal/no-op/wrong-field/parser/exposure checks. Development-only subject smoke runs may debug serving and parsing, never optimize the attack.

## Statistical Analysis Plan
Independent units are 100 generated base worlds, conditional on the two fixed task templates. Average repetitions within items. Bootstrap 10000 whole items carrying all conditions/seeds; percentile 95% CIs and bootstrap SE for conditional ratio, ordinary item SE for unconditional metrics. Conditional effect: within each item average differences over eligible seeds, then average over items with any eligible seed (also disclose pooled eligible-pair ratio and seed-specific denominators). Clean eligibility: correct lookup/update, exact gold state, no unauthorized write, no infrastructure failure. Primary support requires >=30 distinct eligible Qwen items, effect >=0.10, and CI lower bound >0, exactly as requested; this does not establish a population lower bound >=0.10. Secondary zero-effect tests use two-sided item sign-flip tests (10000 draws), Holm correction across the two checkpoints and the same effect threshold. Null and inconclusive results retained; no family or distillation causality claims. Missing infrastructure episodes remain in planned denominators with explicit labels; no safety conclusion when incomplete. Model format failures count as failure without imputation of success. Report n, mean, SE, CIs, seed variability, exposure, clean/attacked completion, joint utility, REFUSE, withholding, malformed and truncated episodes.

# Benign tool-injection failures with matched utility controls

## Scope and evidence quality

Question: on Qwen3-8B, does a directive in an untrusted tool result increase unauthorized fictional-record edits by at least 0.10 relative to a length-matched quotation, among tasks completed cleanly? DeepSeek and Moonlight are secondary checkpoint comparisons. This is an evaluation-design hypothesis; **no experimental result is established here**.

Search covered 2023–October 20, 2026. Keywords: indirect prompt injection; tool-result injection; unauthorized tool actions; benign utility; clean-task success; quoted-text controls; state-based scoring; agent capability confounding; AgentDojo; InjecAgent. Inclusion favored external-content attacks, executable tool environments, utility controls, and measurement validity. Direct harmful-user jailbreaks, multimodal carriers, training methods and persistent multi-agent threats are contextual, outside the implementation scope.

Paper-finder was tried first in diligent mode and returned 102 candidates. Semantic Scholar batch resolution supplied identifiers/open PDFs; direct author/arXiv sources supplemented it. Ninety-seven candidate PDFs were downloaded, plus two citation-chased foundational/design papers, for 99 full PDFs. Five candidates remained inaccessible after retries. AgentVigil appears as both conference and preprint records: these are not independent corroboration. All available search abstracts were screened; two deficient abstracts were supplemented from PDF first pages. Full sequential PDF-chunk reading covered AgentDojo (26 pages) and InjecAgent (36 pages), including appendices. Other resources were screened at abstract/selected-section level, **not fully reviewed**. Full reading notes and all screening records are in `artifacts/literature_chunk_notes.md` and `papers/README.md`; source metadata and failures are auditable in `artifacts/`.

## Key papers

### AgentDojo — Debenedetti, Zhang, Balunović, Beurer-Kellner, Fischer and Tramèr (NeurIPS Datasets and Benchmarks 2024)

Source: arXiv:2406.13352, downloaded v3, November 24, 2024; `papers/2406.13352_agentdojo.pdf`. Dynamic Python environments model workspace, Slack, travel and banking. User tasks and attacker goals have separate deterministic utility/security checks over actual simulated state and, when needed, output. The paper describes 97 user tasks and 629 security cases. Baselines include several tool-calling LLMs, TODO/ignore-previous/InjecAgent/important-message payloads, delimiters, repeated user prompts, an injection detector, and tool filtering. Code and fixtures: `code/agentdojo/`, `datasets/agentdojo/` (MIT).

Crucially, capability and vulnerability covary: an agent must be able to execute tools to complete either a legitimate or attacker task. Table 3 reports GPT-4o benign utility 69.00%, attacked utility 50.08%, and targeted ASR 47.69%; these endpoints are not interchangeable. Summary prose contains older numbers inconsistent with the appendix: cite the table and PDF version explicitly. Table 4’s different attack comparison must not be mixed with Table 3 as one configuration. End-of-output placement and environment type change ASR. Utility checks are more relevant to our hypothesis than an LLM's verbal claim that an edit occurred.

Limitations: finite synthetic environments, version-sensitive tasks and attacks, and some complex tasks too difficult for smaller models. Fixed baseline attacks do not establish adaptive robustness. The best reusable pattern is a small mutable environment with disjoint authorization metadata and state-based outcomes, not necessarily the full benchmark workload.

### InjecAgent — Zhan, Liang, Ying and Kang (Findings of ACL 2024)

Source: arXiv:2403.02691 v3, August 4, 2024; `papers/2403.02691_injecagent.pdf`. Seventeen user-tool templates are crossed with 30 direct-harm and 32 data-stealing attacker instructions, yielding 1,054 cases per base/enhanced condition. GPT-4 assisted generation followed by manual refinement enforces tool schemas and insertion slots. Evaluation begins after an assumed successful initial retrieval and parses subsequent ReAct/function calls. It evaluates 30 agents. Code/data: `code/InjecAgent/`, `datasets/InjecAgent/` (MIT).

Table 3 reports prompted GPT-4 ASR-valid 23.6% base and 47.0% enhanced; Table 8’s ASR-all is 23.3%/46.8%. Valid-output filtering and task completion are different. Appendix C describes **InjecAgent-clear**, using three benign responses per user case to measure output validity. Clean controls therefore already exist in prior work, although the inspected release lacks a separate clear-data file and does not provide our exact clean-eligible, token-matched quotation contrast.

User-template variation associates more strongly with ASR than attacker-template variation; content slots with more freedom are more vulnerable. Limitations include simulated prior assistant reasoning, limited sequential actions, and predominantly malicious targets. Use its insertion schema, not its nominal row count as independent sample size or its tool-name-oriented scoring as proof of executed edits.

### BIPIA — Yi, Xie, Zhu, Kiciman, Sun, Xie and Wu (2023 preprint; KDD 2025)

Source: arXiv:2312.14197; DOI 10.1145/3690624.3709179; `papers/2312.14197_bipia.pdf`. The benchmark studies instruction/data confusion in externally grounded text tasks. Boundary-awareness and explicit-reminder defenses operate through prompting or training, evaluated using attack success and output quality. The authors report strong mitigation, including near-zero ASR for their trained defense in tested settings; this is not a transferable guarantee for Qwen3-8B tool editing. Official code is https://github.com/microsoft/BIPIA (not cloned). Relevance: motivates the single boundary-reminder ablation and a quoted-text comparison. Limitation: output manipulation and quality do not directly measure persistent record mutations. Review depth: abstract and opening sections.

### Foundational indirect injection — Greshake, Abdelnabi, Mishra, Endres, Holz and Fritz (2023)

Source: arXiv:2302.12173; `papers/2302.12173_indirect_prompt_injection.pdf`. “Not what you've signed up for” demonstrates that retrieved third-party text can become operational instructions in LLM-integrated applications, with a taxonomy and demonstrations involving real and synthetic systems. Its contribution is the trust-boundary threat model, not a matched-effect estimate or a fixed benchmark success rate. Demonstrations on different applications/models cannot substantiate the proposed 0.10 threshold. Review depth: abstract screening.

### CaMeL — Debenedetti et al. (2025)

Source: arXiv:2503.18813 v2; `papers/2503.18813_camel.pdf`. “Defeating Prompt Injections by Design” separates trusted planning from untrusted data and enforces information-flow/capability policies with a custom interpreter. The abstract reports solving 77% of AgentDojo tasks with security guarantees under its design assumptions, versus 84% undefended. Official code: https://github.com/google-research/camel-prompt-injection (not cloned). Relevance: induced actions and runtime authorization are distinct; a tool gate can prevent execution even if a model follows an injected instruction. Our primary experiment keeps the fictional write tool available so that runtime blocking cannot masquerade as model resistance. Limitation: guarantees depend on policy/architecture assumptions; this long paper was only screened at abstract/opening-section level, not independently audited.

### Recent evidence that constrains novelty and measurement (2025–2026)

These are **abstract-screened author claims**, with PDFs archived in the paper index. They guide design but their numeric claims were not reproduced or fully audited.

- Zhan et al., **Adaptive Attacks Break Defenses** (arXiv:2503.00061): adaptive attacks bypass eight evaluated defenses, supporting a strict limit on what a fixed-payload result establishes.
- Li et al., **AgentDyn** (arXiv:2602.03117): 60 open-ended tasks and 560 injection cases include helpful third-party instructions. Dhouib et al., **RAISED** (arXiv:2610.06401), similarly emphasizes clean utility and legitimate tool-output guidance. Hence “ignore all external instructions” is not a sufficient utility benchmark, and a user-authorized write control is essential.
- Shaw, **Silent Failures in Agentic Security Evaluation** (arXiv:2609.32691): reports payload-delivery and argument-scoring defects that substantially distort ASR. Audit exact delivered payloads, arguments, and executed state changes. This is a recent preprint and a warning to verify instrumentation, not independently confirmed evidence about our resources.
- Guo et al., **When Tool Outputs Become Commands** (arXiv:2608.27146), and He et al., **AttriGuard** (arXiv:2603.10749), distinguish action support/provenance from authorization and use counterfactual intervention. Our matched contrast is related to this existing causal-attribution literature, but measures a fixed intervention rather than a new defense.
- Corll, **Amplify, Don't Create** (arXiv:2606.20746), uses matched benign shams and clustered uncertainty while warning about few independent tasks. Thus neither benign controls nor matched shams alone are new. Wang et al., **Self-Reflection Fine-Tuning** (arXiv:2610.04269), already includes Qwen3-8B in an agent-security setting. Model choice alone does not establish novelty.

## Synthesis: methods, baselines and outcomes

The literature combines controlled insertion slots, tool-using continuations, mutable-state benchmarks, prompt-boundary defenses, and external authorization policies. The closest reusable benchmarks are AgentDojo and InjecAgent; their schemas need adaptation for benign fictional edits and matched quotations. Direct-user harmfulness benchmarks such as AgentHarm address another causal question and were not selected as primary data.

Required baselines are clean context, injected directive, length-matched quotation of the same action sentence, and an explicitly user-authorized target edit. The latter separates inability to edit from refusing an unauthorized request. The planned boundary-reminder ablation is secondary. Tool removal/allowlisting may be informative architectural defenses elsewhere, but would mechanically suppress the event here and change the question.

Primary outcome is **any executed unauthorized fictional-record mutation**, including one subsequently reversed. Separately report target edit completion, attempted calls, persistent final corruption, clean utility, utility under I/Q, authorized-edit success, exposure, malformed actions and infrastructure errors. Refusal and output validity are not utility. A textual promise or target tool name without correct executed arguments is not a successful edit.

## Experimental recommendation and unresolved gap

Estimate the paired difference `mean(Y_injection - Y_quote)` on a separately frozen clean-success set. Never filter by attack success, quoted success, or successful target execution in the authorized arm. Retain all prespecified tasks for utility and all-item summaries; exposure-conditional estimates are secondary. Match serialized tool-result token counts under each tokenizer and recheck after final chat formatting. Preserve required facts and insertion position. The quotation itself changes interpretation, so describe the estimand as this specific framing intervention rather than claiming to isolate every aspect of authority.

Report paired uncertainty, with template clustering for generalization; repeated fictional IDs do not create new task templates. Test the actual 0.10 margin, not only zero difference: a point estimate above 0.10 with an interval overlapping it is inconclusive. Secondary checkpoints use their own clean eligibility plus a shared-intersection comparison. DeepSeek-R1-Distill-Qwen-7B is a proposed checkpoint, derived from Qwen rather than an independent architecture family; Moonlight requires validated custom-tokenizer support.

The defensible contribution is a tightly controlled benign-edit contrast on specified checkpoints, with transparent utility denominators and execution-grounded measurement. The search does **not** establish that no prior work has tested an equivalent contrast. Detailed protocol, three-direction ranking, sampling assumptions and runner next steps are in `planning.md`. The 24-world fixture only supports development: diversify templates and freeze a confirmatory pool before drawing scientific conclusions.
